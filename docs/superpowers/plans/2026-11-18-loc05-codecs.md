# LOC-05 Additional Codecs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `--packaging loc` publishes HEVC, Opus, AV1 and VP9 in addition to H.264/AAC-LC, on every input path where the codec can arrive.

**Architecture:** A `LocCodecProfile` registry replaces the H.264/AAC assumptions in `encoded_sample.cpp` and the object-API gate in `moqt_session.cpp`. Each codec is one profile (sample entry match, extradata extraction and validation, bitstream keyframe detection, codec-string check). Downstream code (`loc_packager.cpp`, DASH/SRT ingest, catalog) keeps calling `loc_codec_config()` and `read_*_samples()`, which dispatch through the registry.

**Tech Stack:** C++20, CMake (Unix Makefiles tree in `build/`), FFmpeg + Bun for `scripts/test-loc05.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-18-loc05-codecs-design.md`

## Global Constraints

- Draft 18 or later only; one ordered subgroup per GOP for video, one sample per group for audio.
- LOC-05 property IDs unchanged: Timescale `0x08`, Frame Marking `0x09`, Audio Level `0x0C`, Video Config `0x0D`, Audio Config `0x0F`, Timestamp `0x10`, Codec String `0x11`. Never emit LOC-01 IDs.
- Codec strings follow the WebCodecs registry: `avc1.`, `hvc1.`/`hev1.`, `opus`, `av01.`, `vp09.`, `mp4a.40.`. Every `0x11` value must byte-match `TrackDescription::codec` / `LiveTrack::codec`.
- AVC and AAC output stays byte-identical; CMAF and LOCMAF bytes do not change.
- Reject, never pass through: unvalidated extradata, encrypted input (`encv`/`enca`/`protection`), mid-stream config changes, layered or multi-picture samples, libmoq with LOC.
- SRT (MPEG-TS) accepts H.264, AAC and HEVC only; AV1, VP9, Opus on SRT fail with a clear message before publishing.
- Frame-marking independence comes from the bitstream, not the container sync flag (`sync && bitstream_key`).
- No emoji; no Claude attribution lines in commits. Build with the existing `build/` tree (`cmake --build build -j`); never bare-reconfigure cmake.

## Review Focus

- Two pictures or access units packed into one MP4 sample (HEVC, AV1) are rejected, not published as one object.
- Explicit object API with a codec string that disagrees with the init data (for example `hvc1.` string with avcC bytes) is rejected.
- Opus `dOps` with channel mapping family 1 (more than two channels) and a truncated `dOps` convert correctly or are rejected.
- After a dropped keyframe, a delta frame never starts a group, for every video codec (late-join recovery).
- AV1, VP9 or Opus on SRT, and unsupported entries such as `vvc1`, fail with a clear error before any publishing session opens.

**Interfaces:**
- Produces:
  ```cpp
  struct LocSampleCheck { bool independent = false; std::optional<std::vector<std::uint8_t>> normalized; };
  class LocCodecProfile {
  public:
      virtual ~LocCodecProfile() = default;
      virtual bool matches(const TrackDescription&) const = 0;                 // sample_entry_type + handler_type
      virtual std::vector<std::uint8_t> extract_config(const TrackDescription&) const = 0; // validated extradata; empty only if has_config()==false
      virtual bool has_config() const { return true; }
      virtual LocSampleCheck check_sample(const TrackDescription&, std::span<const std::uint8_t> sample,
                                          bool strip_matching_config) const = 0; // throws std::runtime_error
      virtual bool accepts_live_track(std::string_view codec, std::span<const std::uint8_t> init_data, bool video) const = 0;
  };
  const LocCodecProfile* find_loc_profile(const TrackDescription&);               // nullptr if unsupported
  const LocCodecProfile* find_loc_profile_for_codec(std::string_view codec, bool video); // by codec-string prefix
  ```
