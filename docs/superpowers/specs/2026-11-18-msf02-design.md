# MSF-02 catalog conformance design

Date: 2026-11-18. Status: approved.

Source text: [draft-ietf-moq-msf-02](../../draft-ietf-moq-msf-02.txt), published
15 November 2026. SHA-256
`171b0dec53aa312baa2c807c1ac24377672c8a7c01adc30cbd0f7e6124ec851a`. Download:
<https://www.ietf.org/archive/id/draft-ietf-moq-msf-02.txt>. There is no
CMSF-02 yet (404); CMSF-01 keeps governing the CMAF-specific fields.

## Intent

Relays that expect LOC-05 expect an MSF-02 catalog. Make every catalog, delta and
MSF URL the publisher emits conform to MSF-02 for all packagings (CMAF, LOCMAF,
LOC, timelines), while keeping MSF-01 output available and byte-identical.

## Goals

- `--msf-version 01|02` (CLI) and `PublisherConfig::msf_version`, default `02`.
- One version profile in `msf_catalog.cpp` drives the catalog `version` string
  (`"1"` or `"draft-02"`, the latter from the draft's examples; section 5.1.1 says
  only "the version of MSF referenced"), the accepted field set, the required-fields
  table and the initDataList types.
- Under `02`:
  - Track namespace is a `/`-delimited string of 1 to 32 non-empty fields; track
    names are non-empty; the Full Track Name is unique.
  - `depends` entries may be track names or `renderGroup` numbers and must all
    resolve.
  - New track fields `packagingMetadata`, `accessibleWindowTime`,
    `keyframeSpacing`, `parentName`/`parentNamespace` (for `update`), the `data`
    role, and `connectionURI` (renamed from `connectionUri`) are modelled and
    validated. `token` was removed from the draft; it was never modelled, and
    stays reserved against custom fields.
  - Table 6 required fields per (packaging, role): `loc` audio needs `codec`,
    `bitrate`, `samplerate`, `channelConfig`; `loc` video needs `codec`,
    `bitrate`, `framerate`; `eventtimeline` needs `eventType`.
  - LOC decoder config is published through `initDataList` entries of type
    `object-property` (VIDEO_CONFIG `0x0D`, AUDIO_CONFIG `0x0F`); the LOC objects
    already repeat those properties. A codec without a description (VP9) has no
    `initRef`. CMAF and LOCMAF keep inline init data.
  - Delta updates carry `generatedAt` and no other root field, support the
    `update` op, and the catalog publisher uses `update` for attribute changes
    instead of falling back to a full catalog whenever the change is expressible.
  - The reserved MSF URL fragment parameter is `cat` (was `c4m`); the parser
    accepts both.
  - Event timeline index keys are uppercase (`T`, `L`, `M`); `data` stays.
  - The media timeline uses `floor` milliseconds and references a `renderGroup`
    in `depends` when every track of that group is covered.
  - `keyframeSpacing` is emitted for tracks in an alternate group when the
    objects-per-group is known.
- `--msf-version 01` output is byte-identical to today's.

## Non-goals

- `MSF_COMPRESSION` (0x78), Track-property delivery in PUBLISH/SUBSCRIBE_OK/FETCH_OK
  (the `track-property` initDataList type is accepted by the validator but never
  emitted), secure objects, log and metrics tracks, `packaging: "catalog"`,
  `clone` delta op, subscriber-side fast track switching, the MSFTS example.

## Anti-goals

- Any byte change to `--msf-version 01` output.
- Hand-assembled catalog JSON outside `serialize_catalog()`.
- A catalog that fails its own validation because a required field (for example a
  live `framerate`) is unknown at serialization time.

## Constraints

- `MsfCatalog::version` stays the single source of truth for the profile, so a
  delta (which omits `version` on the wire) still knows its profile; the library
  default for the struct stays `"1"` and every product emitter sets it from
  `PublisherConfig::msf_version`.
- Packager entry points take a trailing `MsfVersion` parameter defaulting to `k02`;
  tests that pin `01` bytes pass `k01` explicitly.
- The percent rule (section 5.4.1) and existing CMSF content protection behaviour
  are unchanged.

## Approaches

- A. Switch outright to MSF-02: smallest change, breaks every `"version": "1"`
  consumer immediately.
- B. Version profile with `--msf-version 01|02`, default `02` (chosen): one
  serializer, two tested code paths, older relays stay reachable.
- C. Dual catalogs: impossible, there is one catalog track.

## Decisions made by the author (correctable)

- initDataList `data` for property entries is `"0x0D"` / `"0x0F"` (the draft only
  says "hex notation").
- `packagingMetadata` / `streamMapping` is not emitted: group mode is the default
  and is what we send.
- The 02 media timeline uses `floor`; the 01 path keeps today's rounding to
  preserve its bytes (both drafts say floor, so the 01 behaviour is an existing
  nonconformance recorded in the docs).
- A missing live `framerate` is resolved like `bitrate`: measured, else a
  codec-class default flagged as estimated.
- A delta whose attribute change removes a field falls back to a full independent
  catalog, since `update` can only override.

## Left to the builder

- Exact parameter threading through the packager and live ingest overloads.
- The per-field comparison used to build `update` tracks.
- Test fixture construction.
